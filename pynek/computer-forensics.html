Computer Forensics

The operating system remembers more than the user does

Most people assume that deleting a file, clearing a browser and emptying the recycle bin removes the evidence. It removes the convenient copy. Windows, macOS and Linux each maintain a dense layer of artefacts that record what ran, what was opened, what was connected and what was searched — registry hives, shellbags, prefetch, jump lists, LNK files, event logs, journal records, spotlight metadata and shell history among them.

We acquire a forensic image of the machine through a write blocker, verify it against the source hash, and examine the copy. The examination is driven by the question you asked: whether confidential files were copied to a USB device before a resignation, whether a machine was used to send a particular e-mail, what a piece of malware did after it executed, or simply what a user did during a defined window.

The output is a documented timeline with the underlying artefacts cited, so that a second examiner could follow the same path and reach the same conclusion.

Coverage

What the examination reaches

Deleted and residual data

Recovery from unallocated space, file slack, shadow copies, journal records and carved file signatures — including partial files whose directory entry is long gone.

User activity timeline

Logons and logoffs, application execution, document access, searches, browser history and USB connections, correlated into a single time-ordered view.

External device history

Which USB devices were attached, when, by which account, and which files were opened from or written to them — the core question in most data theft matters.

Internet and cloud activity

Browser history across profiles, downloads, webmail traces, cloud sync client logs, and evidence of data uploaded to personal accounts.

Local mail stores

PST, OST, MBOX and EML archives, including deleted items and messages present in the store but absent from the mail server.

Anti-forensic activity

Evidence of wiping utilities, mass deletion, timestamp manipulation, log clearing, and the gaps those actions leave behind.

Questions

What clients ask first

Will this stand up in court?

The examination is conducted so that it can. Acquisition is write-blocked and hash-verified, custody is documented from receipt to return, the method is recorded in enough detail to be repeated by another examiner, and the report carries a named examiner’s statement. Where an electronic record is to be produced, we supply the certificate required under Section 63 of the Bharatiya Sakshya Adhiniyam, 2023 (previously Section 65B of the Indian Evidence Act, 1872). Admissibility is ultimately a matter for the court, and your counsel should review the material before it is filed.

How is the evidence handled once it reaches you?

It is logged on receipt with photographs, serial numbers and visible condition, stored in a secured area, and entered on a custody record that captures every subsequent transfer with date, time and signature. Examination is performed on a verified working copy — the original is not analysed directly. The original is returned to you or held under instruction, and the custody record forms part of the report.

The user wiped the machine. Is it worth examining?

Usually, yes. A reinstall does not necessarily overwrite the whole disk, and a quick format overwrites almost nothing. Even where wiping software was used, its own execution leaves artefacts — and the fact that deliberate wiping occurred, with a timestamp, is frequently more probative than the files themselves. We will tell you after acquisition whether continuing is worth the fee.
